# Constellation

**From implementation to mechanism.**

Constellation is a public research notebook for extracting reusable architecture ideas from software, AI systems, tools and experiments.

The aim is not to catalogue products or copy implementations. It is to understand the mechanism beneath them: what problem a system is actually solving, which ideas are essential, which are incidental, and how the useful parts can be reinterpreted in a different context.

## Working method

1. Observe the system as it exists.
2. Abstract away product language and implementation detail.
3. Identify the underlying mechanism and constraints.
4. Apply different lenses to expose assumptions, tradeoffs and hidden dependencies.
5. Reduce the idea to what is actually needed.
6. Reinterpret it for a new problem or architecture.
7. Record the reasoning so the concept can evolve rather than being rediscovered.

A recurring question is simple:

> Are we solving the real problem, or focusing on the most visible part of the current solution?

## Current themes

* Agent harnesses and runtime boundaries
* Agent orchestration and evaluation
* Context, memory and semantic compression
* Human authority, evidence and acceptance
* Architecture patterns that survive implementation changes
* Research notes on emerging AI systems

## Related work

**Skill Evaluation Graph** turns evaluation into an explicit evidence and acceptance system.

**Semantic Packetisation** explores the minimum sufficient semantics required to move work and evidence between models without losing decision critical meaning.

**Astra Quota Router** explores routing by decision risk, preserving expensive judgement for the work that actually needs it.

These projects are implementations or experiments. Constellation is the reasoning layer where broader concepts can be inspected before they become architecture.
